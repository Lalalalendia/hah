# Yandex RAR Rescue v0.9 — адресное восстановление файлов

Экспериментальное Chromium/Яндекс Браузер расширение для **публичного** архива
`Диск 2.rar`:
https://disk.yandex.ru/d/_RSlWomRWmty1w

Прямое скачивание оригинального RAR размером 244 374 677 байт ранее
возвращало HTTP 500. Встроенный просмотрщик, однако, позволяет скачивать
отдельные элементы.

## Что проверено в настоящем просмотрщике

- Обнаружено **1286 / 1286** объектов: **1199 файлов и 87 каталогов**;
  в манифесте 88 каталогов, включая виртуальный корень. Ошибок
  инвентаризации и неопределённых объектов нет.
- В v0.7 подтверждена автоматическая загрузка `LOG4J.XML` (1760 байт,
  примерно 10 секунд от клика до завершения).
- Пользователь подтвердил, что при проверке v0.8 файлы сохранились
  **с правильной вложенной структурой**.
- v0.8 при этом прошёл по **всем папкам** даже ради двух выбранных
  файлов. Это дефект архитектуры навигации, а не обязательное
  поведение браузера.

**Не доказано:** восстановление всех 1199 файлов, CRC/SHA целостность
каждого файла и работа v0.9 на реальном просмотрщике.

## В чём отличие v0.9 от v0.8

| Операция | v0.8 | v0.9 |
| --- | --- | --- |
| Первичная инвентаризация | Полный обход (правильно) | Полный обход (не изменён) |
| Два контрольных файла | Полный DFS по 87 папкам | Переход только к двум известным каталогам и их предкам |
| Массовая выгрузка | Полный повторный DFS | Каталоги группируются по наличию оставшихся файлов |
| Переключение между каталогами | Возврат через общий DFS | Маршрут через **наиболее глубокого общего предка** (LCA) |
| Возобновление | Посещаются и готовые каталоги | Завершённые пути и каталоги без ожидающих файлов пропускаются |
| Проверка правильности пути | Манифест и адрес загрузки | То же + сверка листинга каждого посещённого каталога |

Например, если нужен `HELP/SUB/A.TXT`, алгоритм открывает только
`HELP` и `SUB`. Для следующего `HELP/OTHER/B.XML` он возвращается
только в `HELP`, затем открывает `OTHER`. Каталоги `PLUGINS`,
`JRE` и другие посторонние ветки **не посещаются**.

Это не прямая загрузка произвольного элемента по его пути. Пока у
Яндекс-просмотрщика не подтверждён безопасный API перехода к папке,
каждый компонент пути всё ещё нужно открыть через штатный интерфейс.
Но **исследовать всё дерево для этого не нужно**.

## Алгоритмы

- `archive-crawler.js` — первоначальный DFS для создания манифеста
  и обнаружения всех папок и файлов.
- `archive-navigator.js` — адресные переходы `NAV_START` / `NAV_GOTO`
  к каталогам из проверенного манифеста. Сверяет содержимое посещаемой
  папки с исходным списком. При несовпадении **останавливается**.
- `recovery-plan.js` — выбирает два контрольных вложенных файла или
  группы каталогов с ещё не скачанными файлами. Объекты со статусом
  `armed`, `awaiting`, `needs-review` не запрашиваются повторно.
- `frame-sensor.js` — находит локальную кнопку `Скачать` внутри
  нужной строки. Для адресной загрузки проверяет, что навигатор
  находится в требуемой папке.
- `background.js` — сопоставляет `chrome.downloads` с точным
  исходным путём, допускает запоздалые ответы и не начинает новый
  запрос при неопределённом результате.

Все исполняемые файлы из архива скачиваются только как данные,
**никогда не запускаются**.

## Установка и возобновление

1. **Сохрани** `Disk-2.rar-recovery-report.json` перед обновлением.
2. Из последнего **успешного** GitHub Actions `RAR Rescue Extension Checks`
   скачай `rar-rescue-v09` и распакуй единожды.
3. Желательно **заменить файлы в уже установленной папке расширения и
   нажать «Перезагрузить»** в `browser://extensions`. Это сохраняет
   идентификатор расширения, локальную карту и журнал загрузок.
   Удаление расширения может уничтожить его локальные данные.
4. Обнови страницу Яндекс Диска и открой **корень** `Диск 2.rar`.
5. Нажми `1. Найти файлы`. Если локальная карта утрачена,
   импортируй сохранённый JSON (импорт проверяет 1286 объектов и
   пути, но сбрасывает недоказанные статусы загрузок).
6. Если два вложенных файла уже были успешно учтены в локальном
   журнале v0.8, нажми **«Восстановить подтверждение без повторного
   скачивания»**. Расширение сверит их пути, байты и разметку
   кнопки скачивания, не нажимая её.
7. После этого **6. Скачать всё со структурой** использует новый план:
   только папки с оставшимися файлами, по одному запросу на файл.
   Пользователь может остановить проход после текущего файла.
   В отчёте сохраняются исходные пути, байты и ошибки.
8. Если доказательства вложенной проверки не сохранились, нужен
   контрольный тест двух вложенных файлов. Переходить к массовому
   скачиванию без подтверждения структуры нельзя.

## Состояния скачивания

`downloaded` — браузер завершил ненулевую загрузку **в точном
ожидаемом каталоге**. Это не равно CRC/SHA проверке содержимого.

`needs-review` — результат неизвестен или путь не совпал:
**никаких автоматических повторов**. Яндекс может доставить файл
после длительной задержки.

`pending` — файл ещё не запрашивали.

Полный алгоритм выдаёт JSON-отчёт. Пустые исходные папки можно
создать отдельным действием с явно выбранным каталогом в браузере.

## Проверки

- `extension/tests/recovery-plan.cjs` — пропуск готовых файлов и
  каталогов, запрет зависших, выбор двух текстовых файлов из разных
  родительских папок.
- `tools/test_direct_navigation_fixture.py` — настоящий headless Chrome,
  модель 88 каталогов. При переходах в `HELP/SUB`, `HELP/OTHER`,
  `REPORT`, `PLUGINS` открываются **5 нужных каталогов**, а не
  87; проверяется наиболее глубокий общий предок, скачивание
  одноимённых файлов и защитная остановка при изменении состава папки.
- `tools/test_recursive_fixture.py` — прежняя проверка полного
  DFS-инвентаризатора.
- `extension/tests/download-history.cjs` — запоздалые браузерные
  загрузки, запрет дубликатов и сохранение точных вложенных путей.
- `extension/tests/import-manifest.cjs` — безопасный импорт карты
  1286 объектов.
