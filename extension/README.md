# RAR Rescue v0.10 — безопасное продолжение после частичной выгрузки

**Статус:** новый режим продолжения проходит CI и требует проверки на настоящем Яндекс Браузере. Все изменения находятся в Draft PR #1.

## Факт из пользовательской диагностики

- `Диск 2.rar`: **1286 объектов**, 1199 файлов и 87 папок. Карта полная, проблем обхода нет.
- **129 файлов скачаны** и отмечены в локальном журнале.
- Два вложенных файла `IHE_PDI/10000000/10000001/SERIES.HTM` и
  `IHE_PDI/10000000/10000003/SERIES.HTM` подтверждены на исходных путях.
- Последний запуск был заблокирован сообщением
  `Previously requested files require manual review` из-за одного старого
  запроса с неизвестным результатом (в логе путь обрезан).
- До восстановления учёта оставалось **1070 файлов**, включая спорный.
  Не следует повторно скачивать ни один из 129 готовых файлов.

## Что изменено в v0.10

В v0.9 любое состояние `needs-review` останавливало **всю** очередь.
Это неверно: одна неопределённая загрузка не должна блокировать остальные
файлы с другими именами.

В v0.10:

1. Новый **планировщик** делит манифест на четыре группы:
   - `downloaded`: уже завершённые передачи, не запрашиваются повторно;
   - `pending`: проверенные исходные пути, которые безопасно запрашивать;
   - `needs-review/armed/awaiting/failed`: неопределённые попытки, которые
     **не запрашиваются повторно**;
   - **name-conflict**: другие файлы с таким же именем, которое может
     соответствовать запоздалой загрузке спорного файла. Они также
     временно исключаются для предотвращения неверной идентификации.
2. Кнопка **Проверить спорные загрузки** вызывает только
   `chrome.downloads.search` и сверяет завершённые файлы по **точному
   относительному пути**, ненулевому размеру и разрешённому источнику.
   Если файл уже пришёл, он становится `downloaded` без нового клика.
3. Если старый запрос всё ещё скачивается, продолжение **не разрешается**,
   пока передача не завершится. Если старый клик неизвестен менее восьми
   минут — нужно подождать, а не отправлять новый запрос.
4. После восьми минут без признаков продолжающейся загрузки пользователь
   может безопасно **отложить** этот запрос: исходный путь остаётся
   `needs-review`, никогда не загружается заново автоматически.
   Запрос может позже появиться в браузере — поэтому его имя и
   потенциальные браузерные суффиксы резервируются.
5. После отложения планировщик продолжает **только другие безопасные
   файлы** из каталогов с оставшейся работой. Адресная навигация v0.9
   и точные назначения в Windows сохраняются.
6. Состояния `downloaded`, `needs-review` и потенциальные конфликты
   явно выводятся в интерфейсе и JSON-отчёте. Неопределённые файлы не
   считаются восстановленными, даже если обработка остальных завершилась.
7. Для нового файла по-прежнему действует **один клик**, ожидание браузерной
   загрузки и остановка на новой неопределённой попытке. Встроенных
   автоматических повторов **нет**.

Важно: если отложенная попытка всё-таки появится очень поздно,
Chrome может сохранить её в стандартный каталог загрузок, а не в
структуру восстановления. Это сознательный компромисс: лучше сохранить
файл для ручной сверки, чем сопоставить его с чужим исходным путём.

## Как действовать

1. **Не удаляй** старое расширение до сохранения
   `Disk-2.rar-recovery-report.json`. Обновляй распакованные файлы
   **в той же установленной папке** и нажимай «Перезагрузить»:
   так сохранится `chrome.storage.local` с 129 завершёнными файлами.
2. Установи проверенную CI сборку **rar-rescue-v10**.
3. Открой **корень** `Диск 2.rar`, нажми «Найти файлы».
4. Если требуется, нажми **«Восстановить подтверждение без повторного
   скачивания»**: два вложенных `SERIES.HTM` должны быть уже в журнале.
5. Нажми **«Проверить спорные загрузки»**. Это **не скачивает** файлы.
   Запиши количество `downloaded`, `pending`, `needs-review` и
   конфликтов имён.
6. Если есть всё ещё активная загрузка — дождись её. Если запрос
   старше восьми минут и файл не скачивается, он останется
   `needs-review`, а не будет запрошен повторно.
7. Нажми **«Продолжить восстановление»**. Расширение посетит только
   каталоги с безопасными ожидающими файлами, пропустит ранее
   загруженное и отложенное. Не переключай папки вручную до остановки.
8. Сохрани **Отчёт JSON**. В нём останутся пути и причины, по которым
   отдельные файлы не восстановлены. Их можно проверять и обрабатывать
   отдельно после завершения остальных.

## Ограничения

- Этот вариант **ещё не проверен на реальной выгрузке всех файлов**.
- После отключения/переустановки расширения локальный журнал может быть
  утрачен; экспорт JSON сохраняет карту, но не заменяет проверку файлов.
- Скачанное без CRC/SHA каждого элемента не равно криптографически
  подтверждённому восстановлению.
- Ни архив, ни cookies, ни подписанные ссылки, ни содержимое аккаунта
  в репозиторий не отправляются.
- Исполняемые файлы скачиваются как данные и **не запускаются**.
