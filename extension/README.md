# RAR Rescue v0.7 — без повторных загрузок при задержке Яндекса

**Статус: Draft.** Цель — восстановить содержимое `Диск 2.rar` с оригинальной структурой. Сам RAR целиком отвечает HTTP 500, но отдельные элементы веб-просмотрщика скачиваются.

## Что действительно подтверждено

Реальный обход v0.5 записал **1286/1286 объектов** — 1199 файлов и 87 папок (88 записей каталогов, если считать корень). Это полный манифест структуры, но **не** скачанные файлы. Пользователь подтвердил реальные загрузки `README.TXT` по 2229 байт. Браузер переименовал повторы в `README (2).TXT` … `README (6).TXT`. Предыдущий загрузчик слишком рано завершал ожидание (25 секунд без события, три минуты после запуска), затем повторно нажимал кнопку.

Причина повторов — неверная модель асинхронной операции. Событие `button.click()` не доказывает, что файл сохранён, а отсутствие событий `chrome.downloads` через 25 секунд **не** доказывает ошибку загрузки.

## Что изменено в v0.7

1. **Одна попытка на файл.** После отправки команды файл получает локальное состояние `awaiting`. Новый запрос по тому же пути и параллельный запрос другой позиции блокируются.
2. **Ожидание до 8 минут** появления загрузки и **до 30 минут** её завершения. Каждые шесть секунд проверяется состояние менеджера загрузок браузера. При успехе файл отмечается `downloaded`.
3. Если файл остаётся неопределённым, он получает `needs-review`, и расширение **не делает автоматических повторных запросов**. Фоновый наблюдатель продолжает принимать запоздалые события, даже после закрытия ожидания в интерфейсе.
4. Загрузки из встроенного `docviewer` сопоставляются по ожидаемому имени (включая браузерное `README (N).TXT`), разрешённому домену, времени и единственному ожидающему запросу. Подписанные URL в диагностику не попадают.
5. Браузер должен подтвердить ненулевой файл **именно в** `Downloads/YandexRARRecovery/Disk-2.rar/<папка>/<имя>`. `README (N).TXT` вне целевого дерева считается `needs-review`, а не успешно восстановленным файлом.
6. Если позднее приходит успех, журнал обновляется. В массовой очереди следующий файл запускается **только после подтверждения предыдущего**.
7. Готовая карта v0.5 по-прежнему импортируется через **«Импортировать карту JSON»**; повторно обходить все папки не нужно.

## Как проверить

1. **Сохрани старый** `Disk-2.rar-recovery-report.json`. Удаление расширения может очистить локальный журнал.
2. В последнем успешном CI workflow **RAR Rescue Extension Checks** скачай `rar-rescue-v07`, распакуй один раз.
3. Установи через `browser://extensions` → «Загрузить распакованное расширение». Отключи предыдущую версию, обнови страницу Яндекс Диска и открой корень RAR.
4. При необходимости импортируй старую карту JSON (1199 файлов, 87 папок, 1286 объектов).
5. Нажми **«1. Найти файлы»**, затем **«Проверить автоматический клик»**. Расширение сделает *ровно один* программный клик по текстовому файлу, ещё не отмеченному как скачанный/ожидающий. **Не нажимай повторно**, даже если файл не появился немедленно.
6. Оставь вкладку открытой и дождись итога. При длительном ожидании панель показывает прошедшие секунды, но не повторяет запрос.
7. Если появится `downloaded`, это подтверждает механизм одного файла и правильную папку. Если появится `needs-review`, пришли **«Скопировать диагностику»** и проверь последние загрузки Яндекс Браузера. Пока статус не выяснен, массовая очередь остаётся закрытой.

## Безопасность и достоверность

- Карту сохраняем с исходными относительными путями; расширение не запускает EXE/CMD/SH.
- При конфликте имени Chrome использует `uniquify`, а расширение **не принимает переименованную копию за исходный целевой файл**.
- Состояние `downloaded` означает завершённую браузером ненулевую передачу по ожидаемому пути, но **не** проверку CRC/SHA самого файла.
- Неизвестные результаты останавливают очередь. Не следует вручную перезапускать/удалять расширение и повторять тот же файл до проверки уже начатой загрузки.
- Не загружай в GitHub cookies, токены, подписанные ссылки и HTML авторизованной страницы.

## Направления после подтверждения

- Разрешение `needs-review` только после проверки браузерной истории и явного согласия пользователя, а не по таймеру.
- Независимая сверка `CRC/size` на каждом файле, если метаданные доступны.
- Ограничение общей нагрузки на Яндекс и работа с долгими серверными очередями.
- Экспорт полного отчёта `downloaded / pending / needs-review / failed` по всем 1199 файлам и 87 папкам.
